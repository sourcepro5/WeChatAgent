# 回复协议标记处理

`RESPOND:` 是模型与发送桥接之间的控制标记，发送到微信的正文不应包含这个前缀。

- 解析器在分条前清理明确的行首标记，兼容大小写、中文冒号、重复包裹和每段重复标记。
- 正常英文用法、句中提及、行内代码、引用和完整代码示例保持原样；代码示例保持为同一条消息。
- 无法确认的格式只尝试一次模型校正。仍然无效时不发送，不放宽思考内容或表情引用校验。
- 重启后遇到旧待发草稿中的协议标记时，取消剩余投递并记录状态说明，继续处理新消息。已确认发送的历史和发送操作编号不改写，也不自动重发。

## 语音回复 `RESPOND_VOICE:`

本轮可以发语音时，提示词会附加语音规则，模型可用 `RESPOND_VOICE: 正文`（或 `语音回复：正文`）请求发一条微信语音。可用条件和发送方式见[语音回复](VOICE_OUTPUT.md#逐轮选择文字或语音)。

- 正文只发一条，不超过 400 字，不带表情、链接和代码块。`RESPOND_VOICE: SILENT` 视为沉默，空正文视为无效。
- 本轮不能发语音，或正文不适合朗读时，按 `RESPOND:` 的文字规则处理。
- 这个标记和 `RESPOND:` 一样会被清理，不会出现在微信正文里；混在正文中的标记按协议错误处理。
- 语音段与文字段一样持久保存。重启后，已提交的语音只按原投递 ID 核对回执，不重新合成，也不改发文字；只有合成在提交前确定失败时才改发一次文字。

源码更新后重启 WeChatAgent 后台服务生效，无需删除 DSH 会话、人设或消息记录。语音规则位于 DSH 插件的提示文件中，更新后还需执行“准备项目配置”并完整重启 DSH。已发送到微信的历史消息不会被改动。

隔离回归验证：`npm run test:reply-protocol`。测试使用临时目录和模拟发送器，不向微信发送消息。
