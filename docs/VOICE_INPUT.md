# 微信语音 API 转写

可选插件源码位于 `optional-extensions/speech-recognition/`，交付包为 `optional-extensions/packages/speech-recognition-1.5.0.zip`。安装、授权和配置说明见该目录 README。本功能不预设 API 地址、服务商、模型或密钥。

1.3.0 已将常见服务预设、模型匹配与请求适配移入插件，可在原有支持语音 API v2 的安装版直接导入 ZIP 使用，保持自动协议并填写地址、密钥和模型即可。旧宿主内置检测按钮不能随 ZIP 升级，对新增千问预设可能误报；实际转写由插件处理。

1.2.1 配套界面按“连接服务 → 选择模型 → 测试识别”引导，只需填写服务地址、密钥和模型，其他配置收进高级设置。常见千问与 Whisper 模型自动匹配请求，旧自定义配置继续保留。读取模型仅显示语音候选，仍允许手动填写；未知模型需要明确选择服务类型。

配置页可自动读取接口返回的模型，并分别显示转换组件和识别接口检测结果。模型列表不等于转写能力证明；“检测配置”只上传内置合成测试短句，不使用聊天语音，也不自动启用插件。接口不支持模型列表时保留手动输入，特殊目录可填写模型列表 URL 与 JSON 路径。

## 配套宿主

- `reader-api.py` 接收类型 34，仅为已启用并授权的插件/聊天登记引用，不通过 SSE 传递路径、数据库凭据或音频字节。
- `wechat_voice_input.py` 将引用绑定当前账号、聊天、服务器消息 ID、本地 ID、时间及原发送者；媒体数据库仅查询对应聊天和本地 ID，遇到不同候选字节拒绝选择。
- 带令牌的读取端点 `GET /api/v1/voices/:id?conversationKey=...&pluginId=...&format=wav|silk` 再检查当前账号、聊天和授权；只供宿主使用。
- 插件 API 的 `ctx.audio.read(id,{format})` 需要 `audio_read`，且 id 必须在当前宿主动作的绑定范围内。不会向插件传递读取器令牌或数据库密钥。
- DSH 的认证端点 `POST /voice-input` 调用本聊天唯一一个已获 `audio_read` 授权并注册 `transcribe` 动作的插件（不按插件 id 绑定，见[聊天能力路由](PLUGIN_DEVELOPMENT.md#聊天能力路由)），结果带回处理插件的 id；不创建或切换 DSH 会话，不给模型增加执行权限。
- Bridge 的 `VoiceIngress` 对同一聊天保序，识别失败转为真实的未读取占位；独立聊天不互相等待。转写文字继续经过既有唤醒、管理员、去重、发送限流及回执流程。

权限撤销、账号切换或进程停止后不采用未完成结果。读取和上传有截止时间，全局最多两条识别请求，无自动上传重试。识别过程中重启、断网或服务商响应丢失时，无法证明远端是否已处理或计费；不会伪报成功。

新版宿主随包提供固定版本 `silk-wasm` 解码器（含来源、校验和和许可）。Python 解码桥使用发行版 Node 执行该组件，兼容内置 Python 3.13，不要求 pip 或 pilk。能力检测会运行一段合成 PCM→SILK→PCM；格式、包边界、输入大小、输出时长和进程时间均受限。旧环境仍可使用 `scripts/voice-requirements.txt` 的 pilk 回退。没有本地 ASR 模型或后台下载。只更新插件 ZIP 不会升级旧宿主的解码与检测代码。

模型列表对实时协议给出提示；实时、streaming 或 ASR message 模型不自动选为 HTTP 候选。最终兼容性仍以接口检测结果为准，不预设服务商地址。

## 当前验证范围

测试使用合成 SQLite 媒体表、模拟读取器和本机 HTTP API，覆盖请求映射、鉴权、结果路径、超时、响应大小、跨聊天拒绝、权限撤销、消息顺序和降级。另以合成短句验证过一组现有服务的 HTTP JSON ASR 调用；本地真实微信音频仅用于受授权的解码准备检查。未重放历史消息或自动发送微信回复。

## 1.2 协议与现场诊断

接口设置参考 DSH 的协议与模型接入结构：标准文件转写、两种 Chat 音频映射、Anthropic 原生模型发现及自定义请求。地址保留网关前缀，鉴权按协议生成，目录支持数组与模型别名映射。默认仍不预设任何服务地址、模型或密钥。标准协议要求模型 ID，读取模型成功不等同于语音识别成功。

Bridge 将实际语音处理的受控状态按处理插件写入 `state/plugin-service-checks/voice-input/<插件id>.json`（2026-11-04 前为单个 `speech-runtime.json`，更新后从下一条真实语音起重新记录）。记录绑定设置代次，只有时间、阶段和错误码等元数据；不保存音频、转写或密钥。配置页将它与合成测试区分；较新的真实失败不会继续显示旧的成功。并发超过两条时排队，停止时撤销等待，不自动重传到其他协议。

现场补充验收（2026-10-28，用户自行重发）：实际桥接日志记录新语音 `transcribed`，随后模型完成回复，两段文字均获得 `delivery=confirmed`。验证走正常接收链路，没有代为上传旧语音或重放历史消息。开发版本次 61 项相关回归通过。

1.4.1 的 `config-ui.json` 由当前安装包提供页面布局。宿主页面加载修复会在卸载时销毁旧表单、取消异步请求、清除旧检测状态；用户文档保留。旧宿主仍可转写，更新页面加载器一次后才支持此布局文件。

## 1.5.0 插件自带设置页

配置页从宿主移入插件包：`ui/settings.html` 在沙箱 iframe 中显示连接、模型下拉、测试识别和高级设置，宿主不再内置语音专用的表单、模型控件或检测代码（原 `speech-settings.mjs`、`speech-plugin-console.mjs`、`/api/plugins/speech-recognition/models|check` 已移除）。

- 读取模型、测试识别和启用前校验是插件的设置动作（`models`、`check`、`validate`），由控制台在短时子进程中运行插件代码。需先勾选“允许此插件运行”；不需要先保存、授予 `audio_read` 或分配聊天。
- 页面始终拿不到已保存的密钥；密钥栏留空表示沿用已保存值，由插件合并后调用接口，结果中不回显密钥。已保存的设置与密钥原样保留。
- WAV 转换组件状态和最近一次真实语音结果由宿主的 `voice-input-v1` 状态接口提供给申请 `audio_read` 的插件。合成测试结果只在本次页面中显示，不再写入 `state/plugin-service-checks/speech-recognition.json`；插件卡片只按真实语音结果显示状态。
