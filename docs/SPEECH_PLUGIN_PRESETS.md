# 语音插件独立预设（1.3.0）

服务预设、模型匹配和请求适配位于插件 ZIP 内：

- `lib/presets.mjs`：模型族、预设、地址与网关前缀处理、兼容设置规范化。
- `lib/recognize.mjs`：在验证配置、读取当前语音之前计算有效设置；封装请求、发送一次并提取对应结果。
- `lib/diagnostics.mjs`：插件自身的模型目录与合成短句检测复用相同预设。

宿主页面的 `public/console/speech-setup.mjs` 仅重新导出受审查的插件源码供配置页面使用。1.3.0 起，自动模式的设置由页面原样交给插件，宿主页面不再用旧的模型目录拦截插件新增模型。实际执行入口不依赖这个页面或任何 ZIP 外的预设模块。

## 原安装版使用

原宿主已支持 API v2、`voice-input-v1` 和 `actions-v1` 时，可直接导入 `speech-recognition-1.3.0.zip`，无需更换安装包。更新保留兼容配置，并按原安装器规则重新要求启用与授权。

默认保持自动协议，填写服务地址、密钥、模型；保留默认 WAV，选择聊天与语音权限后保存。常见千问与 Whisper 模型在收到新语音时由插件自动适配。已有显式协议、自定义 JSON、文本结果及字段映射优先保留。未知网关别名沿用已有路径/协议规则，不会自动换模型、换域名或轮流重传音频。

旧宿主内置的“检测配置”不会随 ZIP 更新，可能对新增千问预设误报 404。它不阻止格式有效的配置保存；以新语音的实际转写结果验证新插件。更早且缺少语音宿主能力的版本仍需更新宿主。

## 验证范围

在临时目录复制当前安装版的旧插件宿主代码，先加载旧插件，再导入新 ZIP、重新授权；不更换宿主进程。副本中没有宿主预设目录或前端，千问原生、Qwen3 Chat 音频和 Whisper 文件转写三条模拟链路均成功，宿主代码哈希未变，更新保留密钥和聊天选择。

所有音频为合成数据，接口是本机模拟服务，没有调用真实识别平台、上传聊天录音、安装插件或重启用户软件。本轮原安装器保持不变，交付独立插件 ZIP 与源码更新。
