# DSH 原生会话上下文与命名

## 实现方式

每个 `平台:聊天类型:数字ID` 对应一个当前使用的 DSH session。正常续聊与压缩继续使用同一 ID；用户在 DSH 归档当前会话后，该聊天的下一次配置／消息会创建新一代 session。旧记录继续归档，新会话从一次人格初始化开始。

```text
首次进入／人格变化 → 补入一次完整人格 → 追加新消息
正常续聊           → 只追加未处理的新消息
原生压缩成功       → 下一次模型请求前补回一次人格 → 继续同一 session
```

人格文件保持完整，没有擅自缩短。插件通过本机鉴权接口接收人格配置，将其保存为会话配置；只有需要初始化时，才把完整人格加入模型可见的上下文。正常轮次不重复添加。

Bridge 的本地缓冲用于存档、未处理消息与重试管理，不再每次把最近 20／30 条历史重发给 DSH。模型使用 DSH 已保存的原生历史。

普通图片作为该 session 的 DSH 原生附件输入。成功轮次结束后追加 `image/offload`，保留附件记录，但后续模型请求不继续传入历史图片内容。此操作在原生事件发布结束之后执行，避免递归追加事件；恢复会话时也清理已完成轮次遗留的图片输入。详见 [图片接收与识图](IMAGE_INPUT.md)。

## 压缩后的恢复

本机 DSH 的成功关闭事件为 `compaction/end`，失败事件携带 `error`。插件检查原生 session 的有效 surface 与成功压缩边界，而非只使用进程内布尔标记。

- 首次初始化、人格变更、成功压缩或原生 surface 中已没有初始化消息时，补入人格。
- 在 `agent/pre-step` 的原生压缩中间件完成后，准备下一次初始化。
- 上下文溢出在同一步重试期间发生压缩时，通过 `agent/request` 补回人格。
- 压缩失败时保留仍有效的人格，不重复补入。
- 补入人格与下一次模型请求合并，不单独触发一个 AI 回复轮次。
- DSH 或插件重启后，从原生会话记录判断是否需要初始化，继续使用同一个 session。

固定的无工具安全 preset 仍然保留。群聊原文不能更改工具权限或系统边界。

## 删除窗口或归档会话之后

DSH 的归档操作会阻止该会话继续运行，表现为 `turn_blocked`。仅关闭主窗口不会归档会话。

插件读取 DSH 原生 `workspaceRegistry.archivedSessionIds`。发现映射中的会话已归档时，创建并挂载新的微信安全 session，成功后才更新映射；旧归档和原始日志继续保留。创建失败时，保留旧映射供下一次重试。

新会话保留聊天名称和人格设置，清空上一代的回复缓存及初始化计数；不把旧会话积累的提示词复制进去。消息由 Bridge 未处理缓冲继续提交。每个聊天独立换代，其他聊天仍使用原会话。

`/sessions` 的 `generation` 表示当前代数，`previousSessionCount` 表示保留的旧映射数量。健康接口 `sessionLifecycle: archive-rotation-v1` 表示已加载此修复。

微信安全 preset 单独挂载 DSH 内置的隔离压缩组与 `/compact` 命令，不使用默认编程 Agent 的工具集。插件通过 `agentPresets.serviceFor(agent, 'compaction')` 访问这个 session 所属的原生压缩器。

DSH 的 `meta.agentPreset` 只记录会话元数据。插件在新建和恢复的 `setup` 回调中实际调用 `agentPresets.mount`，确保人格、安全工具限制和压缩器生效；发现已运行的社交 Agent 未挂载正确 preset 时会拒绝继续使用，要求重载。

## 会话名称

使用 DSH 自带的 `sessionTitle.rename`，直接保存可见标题，不额外让模型生成标题：

- `微信私聊｜好友昵称或备注｜人格名`
- `微信群聊｜群名｜人格名`

会话内部 ID 仍按独立聊天键生成，重名联系人不会共享历史。联系人名称或人格名更新后，配置同步会更新可见标题。

首次新消息会自动配置标题；现有白名单聊天可一次性同步：

```powershell
cd C:\Projects\WeChatAgent
npm run sessions:configure
npm run sessions:status
```

这些命令需要 NT 读取器和新版本 DSH 插件已启动。它们只管理 WeChatAgent 的关联会话，不修改 DSH 的其他工作会话。

## 使用原生压缩

可以在 DSH 界面压缩对应 session；也可以调用管理命令，示例中的 ID 需要换成自己的白名单数字 ID：

```powershell
npm run sessions:compact -- wechat:private:123456
```

不传会话键时，会压缩所有可解析的白名单会话。压缩通过 `ctx.compaction.compactNow` 完成，需要原生 Agent 空闲；正在回复时会返回忙碌，稍后重试。

旧会话里已经积累的重复人格仍属于历史。启用新逻辑只会停止继续累积；要立即缩减旧上下文，需要对相关 session 做一次原生压缩。原始会话日志保留，模型可见上下文替换为原生摘要。

压缩本身需要一次摘要模型请求。人格只在新上下文周期补入一次，但模型每次仍会读取当前上下文中的那一份人格，可能计入缓存输入；本功能不会让既有上下文免费。

## 重试与存储

- 同一聊天的请求串行执行，不同聊天仍独立。
- 完成的模型决策按批次 ID 缓存，重复提交同一批消息可复用结果。
- 微信发送失败时，Bridge 保留已生成的回复并重试发送，避免再次请求模型。
- 原 session 映射从旧格式迁移到版本 2，增加人格、标题和缓存状态；旧映射备份为同目录的 `sessions.json.pre-native-context`。

插件实现：`packages/dsh-social-bridge-plugin/native-context.mjs`。

本机 DSH 会缓存已加载的插件代码，首次启用此实现需从托盘完全退出并重新打开。健康接口中 `contextMode: native-session-v1` 表示新实现已加载。
