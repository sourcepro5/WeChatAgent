# 微信引用消息解析

2026-10-07：接入 NT Reader → Hook OneBot → Social Bridge → DSH 的现有消息链，不修改人格卡，不增加独立模型调用。

## 接收与身份

支持本地类型 `49` 与 `(57 << 32) | 49`，同时要求完整 XML 的 `appmsg/type=57`。补查数据库原始 `message_content`，避免 CLI 的显示预览截掉引用原文。其他 appmsg 类型不因此作为普通文字放行。

当前回复来自 `appmsg/title`；引用历史来自 `refermsg`。保留原消息的服务器 ID（字符串，避免大整数精度损失）、发送者、显示名、时间、类型和正文。群聊 `fromusr` 是群号，引用发言人是 `chatusr`；私聊发言人来自 `fromusr`。本地白名单里的真实私聊和群聊记录已用于核对这一差异。

当前消息的发送者仍取数据库发送者，不被 XML 中的引用者替代。Hook 根据当前账号及原群号计算引用来源关系，覆盖载荷中的关系标记；无法确认来源或来自另一群时标记未知。身份匹配只用于接话判断，不授予配置、工具或发送权限，也不证明那段话一定由当前人格发出。

## 模型上下文

`quoteReply` 作为有界结构经过 OneBot 归一化和聊天缓冲持久化。只保存一条当前发言，提示词中分别标注“被引用的历史消息”和“当前发言人的新回复”。引文中的标签会转义，规则变更指令作为历史聊天数据处理。

在群聊 `mention` 模式下，引用本账号的发言可触发决策，模型仍结合正文、相邻发言与上下文判断回应或沉默。引用其他人不自动触发；回复正文中的真实 @ 或唤醒词仍按既有规则处理。`hybrid` 模式继续通过普通消息批次判断。私聊继续按私聊规则处理。

## 边界

XML 上限 100,000 字符，回复保存至多 4,000 字符，引用原文至多 1,600 字符，嵌套引用最多展开 2 层；过长内容标注截断，模型批次仍遵守现有长度限制。DTD、ENTITY、无效 XML 和其他 subtype 被拒绝。

缺少引用原文时仍传递新回复，并说明原文不可用。引用图片、表情包、语音、视频和文件提供类型或文件标题，明确说明未读取附件；不把媒体 XML、下载凭据或附件字节作为聊天文字。支持嵌套 appmsg 引用中的安全文字摘要，不自动下载被引用附件。

本功能解析别人发送的引用回复；发送端仍使用既有文字或原生表情能力。

## 验证

Python 覆盖两种本地类型、群与私聊身份、原始 XML 补查、大整数 ID、媒体占位、缺失内容、嵌套、恶意 XML 和截断。JS 覆盖 Hook → OneBot → 持久化恢复 → 模型提示词、来源关系覆盖、引用他人不误唤醒，以及伴随真实 @ 的接话。

完整项目回归通过 107 项，其中读取器测试另含 22 项 Python 边界验证。真实记录核对仅在本机读取白名单会话，未向联系人发送测试消息。

现场复核 8 条真实引用（5 条群聊、3 条私聊）全部解析成功，5 条群聊均正确取到原发言人。独立 DSH 原生验收会话的两次请求分别正确答出引用人和集合地点、明确说明未提供引用图片内容；两次均未向联系人发送消息，所有人格 MD 文件的摘要保持一致。私有统计保存在 `state/diagnostics/quote-records-live.json` 与 `quote-model-live.json`。
