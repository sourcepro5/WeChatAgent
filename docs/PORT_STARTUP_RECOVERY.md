# 服务端口与启动恢复

启动时先检查配置端口的监听和绑定状态，再探测能否绑定。没有程序在监听，并不代表端口可以使用；其他程序可能已经绑定但尚未监听，Windows 也可能拒绝绑定。

预检查结果只作启动判断，实际服务仍需成功绑定自己的端口。启动完成后核对监听 PID；适配器还需在 `/status` 返回本项目、当前工作目录、进程 PID 和就绪状态。端口被其他程序抢占、旧版适配器未重启或服务身份不符时，不标记为启动成功。

部分 Windows 预览版的 TCP 连接表会把正在监听的行报告为空 `State`。启动检查会把这种 IPv4 回环行同样视为监听候选，但就绪判断以环回 TCP 握手成功为准，端口表只用于核对 PID；仅存在于表中的记录或已绑定但尚未监听的套接字不会被当成启动成功。

错误保留失败阶段、配置端口和可用的系统错误码：

| 提示 | 含义与处理 |
| --- | --- |
| `ADAPTER_PORT_IN_USE` / `SERVICE_PORT_IN_USE` | 端口被占用或绑定。检查占用进程，核对路径与 PID，选中后再次确认才能停止；也可在连接设置修改端口。 |
| `ADAPTER_PORT_DENIED` / `SERVICE_PORT_DENIED` | Windows 拒绝绑定，可能涉及系统保留端口或权限限制。没有占用进程时仍可能发生，请修改对应配置端口。 |
| `SERVICE_PORT_OWNER_MISMATCH` | 启动过程中出现不同的监听进程，请检查占用者，原进程不会自动被结束。 |
| `ADAPTER_IDENTITY_MISMATCH` | 端口没有返回本实例适配器身份，也可能仍运行旧版适配器。先停止、重启本实例服务；必要时检查端口占用。 |
| `READER_CONNECTION_RESET` / `READER_NOT_LISTENING` | 读取接口连接中断或没有监听，请查看 reader.stderr.log 后重新启动服务。 |
| `HOOK_CONNECTION_RESET` / `HOOK_NOT_LISTENING` | 微信发送组件连接中断或未就绪，请查看 hook-init.log，持续失败时使用匹配微信恢复入口。 |

“检查占用进程”包含已绑定但尚未监听的 TCP 端口。检查本身不停止程序；停止仍需选择具体进程、再次确认，并在执行前重新核对进程身份。系统进程、其他用户进程及身份无法核实的进程不能直接停止。

发生启动冲突的配置端口不会因旧的健康缓存而从检查结果中隐藏。端口变更需保存配置并重新启动服务，程序不会静默修改端口、解除系统保留或结束陌生进程。

升级源码或安装器后，需要停止再启动助手服务，才能加载新的启动检查和适配器身份。修复不改变账号配置、人设或聊天记录，也不自动发送测试消息。
