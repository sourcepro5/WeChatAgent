# 微信 4.2.0.12 适配与验收

此适配仅面向 Windows x64 **4.2.0.12**；其他 4.2 构建不自动视为兼容。WeChatAgent 0.4.3 起安装包仅提供此客户端及对应外置组件，不混入旧版微信。升级保留已有客户端选择和用户数据，可在连接设置中切换到 4.2。

## 已验证范围

2026-11-01 至 2026-11-02 核对腾讯数字签名、启动器与核心模块的精确版本，在完整备份微信账号数据库、共享设置和账号绑定后，使用隔离程序目录冷启动并完成登录。验证公开 NT 读取器与当前账号一致，仅向文件传输助手发送一条固定自测文字和一张无个人信息的测试图片，均取得新的本账号发出记录及非零服务器消息 ID；界面确认图片正常显示。另向文件传输助手实发三帧 GIF，数据库记录为原生 appmsg-8 且 MD5 与原始 GIF 相同，界面可见不同动画帧；通过 OneBot 发送的双帧 GIF 同样确认回执，重复投递 ID 未重复提交。

测试未给其他聊天发送消息，没有调用模型。备份、账号标识、凭据、数据库和原始回执不包含在安装包或源码中。构建与回归结果见 Release 的 VERIFICATION.json。

## 启动稳定性修复

旧组件在登录时出现 `0xC00000FD`。独立 64 KiB 小栈宿主复现同样的栈溢出，定位到 DllMain 中约 64 KiB 的路径缓冲：即使只处理进程附加，函数入口分配仍会影响线程通知。

已将路径分配与文件系统处理移到拥有 2 MiB 保留栈的工作线程。DllMain 只保留轻量初始化，保留静态 CRT 所需的线程通知；修复后的组件通过连续 32 个 64 KiB 小栈线程测试，以及实际冷启动、登录、文字和图片发送验收。

## 能力与限制

- 原生文字 API 已接入现有桥接和服务器回执流程。
- 普通图片 API 已实发验收；真实 @ 只完成对象构造探测，未在真实群聊实发。
- 图片和真实 @ 的底层 API 不等于已提供完整的默认 OneBot/模型工具发送能力。
- 原生 GIF 表情已通过 `/SendStickerMsg` 接入现有 OneBot、dsh-meme 和共享表情池发送，使用精确版本的原生 appmsg-8 对象，不转为文件或静态图片。
- 普通文件和原生引用发送不在本 4.2 组件支持范围内。
- 群聊真实 @、长期运行、第二台物理设备安装和完整模型回复链路需另行验收。

## 本机构建与使用

维护者准备获授权且精确匹配的客户端与头文件依赖后，执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/build-hook.ps1 -TargetVersion 4.2.0.12
```

输出位于私有 state/hook/native-4.2.0.12/。每次重新编译都会清除运行验收状态；完成冷启动登录和真实文字、图片、动画表情回执及桥接去重验收后，才可按该构建的精确哈希更新验收记录并打包。不得沿用旧 DLL 的验收结论。

配置使用 hook.expectedVersion 为 4.2.0.12，hook.wechatExecutable 指向 state/hook/wechat-4.2.0.12/Weixin.exe。打开流程使用专用外置装载脚本，继续核对腾讯签名、组件哈希、核心结构、进程归属和单账号状态，不替换客户端系统 DLL。

客户端保护按目录独立保存权限及更新器恢复记录；维护程序文件前先解除对应目录保护。程序目录分离不等于账号数据分离，切换版本前仍需备份微信账号数据。

## 原生表情版本

发送组件使用 `4.2.0.12-stickers-v2` 配置。启动器、核心和组件按精确版本核对，GIF 只从当前账号绑定的受控发送目录读取，并检查格式、大小及 MD5。原始 GIF 字节保留。`ret=0` 只表示已提交；桥接层仍需查到新发出、摘要匹配且服务器消息 ID 非零的原生表情记录。未确认的同一投递不重新上传，避免重复发送。
