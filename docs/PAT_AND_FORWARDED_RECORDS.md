# 拍一拍文字反应与合并转发记录

2026-10-05：实现于现有 NT 读取器、Hook OneBot 和 Social Bridge 链路。

## 拍一拍

读取器校验 `appmsg/62` 的发起人和被拍账号，只有白名单内其他人拍当前账号才进入链路。OneBot 携带独立 `interaction: pat` 标记，不把它伪装成真正的 @。Bridge 保留该提醒信号，让模型结合文字判断回应方式。普通文字中的“拍一拍”不产生这个标记。

真实群拍一拍有时是 `senderUsername` 为空的系统记录。2026-10-05 的现场检查发现，原来的通用空发送者过滤会提前丢弃这些记录；现已在拍一拍类型中先解析 XML 的 `fromusername` 与 `pattedusername`，补出发起人。数据库提供发送者时仍要求它与 XML 发起人一致；自己拍、拍其他群成员、类型不符或无效 XML 继续过滤，普通消息的空发送者规则不放宽。

模型根据本机当前人格、对话关系和上下文选择文字反应。小鲸鱼和洛琪希卡已加入各自的反应习惯；其他人格继续由原生会话中的本机设定决定。仍然遵守现有白名单、最小间隔和回复频率限制。

拍一拍保留相邻文字一起形成模型批次。收到后等待配置中的消息合并窗口（当前默认 3 秒）收集接话；同一窗口重复拍一拍不会无限延长等待。模型结合发起人、时间顺序和前文判断它是否类似 @：有具体问题时优先答问题，单独招呼时按人设反应，不把别人的无关插话自动当成对自己的要求，也不强制每次输出拍一拍台词。

当前 Hook 原生发送后端没有拍一拍接口，本版实现文字回应，不声明实际拍回去。没有加入鼠标、键盘模拟或伪造拍一拍记录。

## 合并转发记录

读取器补取完整 XML，接收 `49` 或 `(19 << 32) | 49` 的本地类型，并再次校验 XML 中 `appmsg/type=19`。其他文件、链接等 appmsg 继续按既有范围过滤。

解析直接 XML、CDATA、转义 XML；提取卡片标题、消息作者、时间、类型和正文，并保留嵌套记录的层次。拒绝 DTD、ENTITY、异常 XML和过大的载荷，不下载记录中的链接或附件，不把 XML 内的发送人当成当前消息的发送者。

界限：XML 至多 512,000 字符；卡片至多 50 条、约 6,000 字；每条文字约 800 字；嵌套最多 3 层。达到限制会标注截断；标题存在但正文缺失时，明确标记无法解析正文。非文字内容以占位说明，不声称已经看过图片或读过文件。

结构化记录随 OneBot 转发并保存在聊天缓冲中，重启后仍能提交。Bridge 单批按实际转义后的提示词长度切分，卡片正文不再沿用普通消息的 500 字预览限制。未进入本批的记录继续保留为未处理消息，下一批提交。全部卡片内容置于聊天数据边界内，嵌入的改人格或权限指令不具备本机配置权限。

## 验证

- 项目回归 86 项通过，包括 Python 解析边界、嵌套和截断、OneBot 传递、拍一拍唤醒、持久化恢复、长卡片分批和消息处理边界。
- 真实 DSH 隔离会话验证：两个人格各自作拍一拍文字反应；正确指出转发记录里的提议人和同意人；读到 500 字之后的正文；卡片内嵌改人格文字后仍回答当前身份。
- 上述模型验证未向微信联系人发送测试消息。运行服务已重启加载，读取、OneBot 和 Hook 状态另行检查；真实微信新卡片与新拍一拍的端到端收发仍以实际收到的消息为准。
