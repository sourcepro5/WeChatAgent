# 独立微信客户端保护

支持项目 `state/hook/` 下配置的独立微信 4.1.10.27、4.1.15.13。开启保护会备份当前权限与更新器，停用版本子目录中的 `WeixinUpdate.exe`，并拒绝当前 Windows 用户对客户端程序目录的写入、删除和子项删除；读取和执行权限继续保留。

客户端保护不修改共享微信更新缓存、聊天数据库、账号凭据、日志或系统微信安装目录。它限制当前用户更新程序对这个独立程序目录的替换，不保证旧版始终允许登录，也不阻止管理员明确解除保护。

新版微信还可能调用共享 `xplugin` 目录中的更新器。本功能不会停用共享更新器；相关进程仍可能出现，对独立客户端程序的替换由目录权限拦截。不要仅凭更新器进程是否存在判断保护状态。

## 开启、查询与解除

控制台“工具 / 客户端维护”提供开启和解除按钮。4.1.15.13 的“打开微信”会先启用保护再启动客户端；4.1.10.27 保留部署 DLL 时临时解除、部署后重新开启的流程。

```powershell
npm run hook:pin
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/pin-hook-client.ps1 -Status
npm run hook:unpin
```

解除时恢复本轮备份的目录权限，以及本轮由本项目移出的更新器。开启前就已停用的更新器保持原状。维护程序文件前先解除保护；再次打开匹配微信会重新启用。

## 恢复记录

每个客户端目录在 `state/hook/client-pins/` 下有独立记录，绑定客户端路径、版本和 Windows 用户。每次新的保护周期会保存一份新的权限快照及更新器备份；重复开启不会覆盖原始快照。

记录目录包含当前 `pin.json`、操作锁，以及每轮的 `root.acl`、`tree-acls.json`、`updater.bin` 等恢复文件。发生文件哈希冲突或恢复记录变化时会停止并保留原文件。不要删除这些记录或把其他客户端的记录覆盖过来。

旧 `client-pin-acl.json` 仅在其路径与所选客户端完全匹配时兼容读取，不会用旧客户端的权限记录覆盖新客户端，也不会重写这份旧记录。

## 边界

- 拒绝项目 `state/hook` 范围外的路径、链接目录或文件，以及不继承目录权限的子项。
- 开启前核对配置版本和腾讯签名。
- 所选客户端更新器正在运行时停止操作，不强制结束它。
- 同一客户端的保护操作串行执行，防止开启与解除相互覆盖。
- 目录权限修改失败会尝试恢复原权限和更新器，并保留恢复记录。
- 此功能不会清空 `AppData` 下的 `patch`、`download` 或 `update.data`。

验证入口：`npm run test:client-pin`。自动测试在临时项目中验证真实 Windows DACL 和恢复行为，不操作系统微信或共享缓存。
