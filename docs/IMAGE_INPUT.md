# 图片接收与识图

## 运行流程

电脑微信同步普通图片消息后，独立 NT 读取器只为当前白名单聊天登记图片引用。外层图片工作进程通过消息服务器 ID、本地 ID、时间及会话附件目录定位本机文件，使用本地媒体解码函数解密图片。不会凭单独的本地消息 ID 在其他聊天中猜图。

SSE 和 OneBot 只携带图片引用，不携带密钥或文件路径。DSH 插件从带令牌的本机读取 API 获取图片，核验所属会话和字节校验值，再保存为 DSH 原生附件。图片直接进入该好友／群的原生 session，无需启用 `read_image` 或本地文件工具。

当前发送端仍回复文字，不支持向微信发送图片。群聊图片遵守原有白名单、唤醒及发言频率配置。

## 表情包

类型 `47` 的表情包使用相同的受限附件链路，带入对应好友／群的 DSH 会话。只从原消息 XML 获取媒体摘要和地址，先读取当前账号缓存；`wechat.media.allowStickerCdn` 为 `true` 时可回源下载消息自带的腾讯 `wxapp.tc.qq.com` 或 `vweixinf.tc.qq.com` 地址。公开示例默认关闭，运行者取得授权后再启用。

回源强制 HTTPS、不使用环境代理、禁止重定向，原始字节上限 8 MiB、下载总期限 20 秒；解密后必须与原消息 MD5 相符。不使用任意 URL、聊天中的链接或模型指定路径，也不扫描进程内存。URL、密钥和原图仅在私有运行链路中处理。

GIF 动画最多解码 32 帧，另受总解码像素限制，最多选三帧形成静态拼图。WXGF 通过固定依赖 `imageio-ffmpeg` 解码，最多处理 24 帧、12 秒、三张采样画面。模型看到的是采样画面，不是完整动画；发送端仍只回复文字。安装依赖请使用 `scripts/reader-requirements.txt`，源码发布包不附带 FFmpeg 程序。

`IMAGE_STICKER_LOCAL_COPY_UNAVAILABLE` 表示本机缓存不能解码且未允许 CDN 回源；`IMAGE_STICKER_DOWNLOAD_FAILED` 可能是远端地址过期或网络故障；`IMAGE_STICKER_CONTENT_MISMATCH` 表示摘要校验不符，不能用其他表情包替代。

部分表情包使用旧 `vweixinf.tc.qq.com` 地址，其 HTTPS 证书可能不覆盖该主机。独立选项 `wechat.media.allowStickerCdnAlias` 默认关闭；获得持续授权后启用，仅将这个旧主机映射到腾讯 `wxapp.tc.qq.com` 并保留原路径和查询。下载凭据会转交该兼容域名，仍通过正常 TLS 验证和原消息 MD5 校验，不关闭证书验证。

## 拍一拍接收

读取器只接受真实 `appmsg/62` 拍一拍字段：消息发起人必须与入站 sender 相符，被拍人必须为当前账号。归一化后进入原聊天会话；群聊添加对群友的明确唤醒，遵守原有白名单和频率限制。不实现主动拍一拍，不处理成员互拍或普通文本伪造的拍一拍。

## 附件失败与群消息积压

群表情包可能带数据库发言人前缀。读取器只移除已核对发言人对应的前缀，再解析 XML；不任意截取聊天文本里的 XML。

附件准备在 DSH 模型轮次之前进行。旧版本中，某张图片无法读取会阻塞整批未读文字，并每 30 秒重试，DSH 会话窗口因而看不到新消息。已修复已知群前缀；如果读取器仍返回附件准备失败，Bridge 仅重试一次文字输入，并明确告知模型本批没有提供图片。原消息仍保留，不会猜测图片内容。会话绑定、完整性校验和模型轮次错误不会通过此方式重试。

限流现在按实际到期时间安排继续处理，避免等待下一次 30 秒轮询。原有频率限制保持配置值；日志 `cooldown wait_ms=...` 表示等待限额释放，`dispatch` 表示提交该批消息，`decision_ms` 包含插件准备和模型响应耗时。群聊 `hybrid` 仍允许 `SILENT`。

模型输出带说明文字时，Bridge 仅采用最后一条明确的 `RESPOND:` 回复段，不把前面的说明发送到微信。支持中文冒号和外层文本代码块。确切的 `SILENT` 仍表示沉默；没有可识别决定的输出会记录 `INVALID_DECISION_FORMAT` 并保留未读消息，不会静默标记为已处理。

## 安装与加载

1. 在项目根目录执行 `npm run setup`，安装固定版本的 Pillow、PyCryptodome 等读取依赖。已有依赖可继续复用。
2. 确认电脑微信登录的是配置中的账号，并同步到图片消息。
3. DSH 必须使用支持图片输入的模型。本机 DSH 自带的 `deepseek-flash` 模型目录声明支持图片；插件在运行时核验实际配置的能力，不支持时返回 `MODEL_IMAGE_INPUT_UNSUPPORTED`。
4. 修改插件后，从 DSH 托盘完全退出并重新打开，再执行 `npm run restart`。健康接口应报告 `imageInput: native-attachment-v1`。

DSH 桌面端已经全局注册图片上下文投影，因此微信 preset 不再次注册 `dsh-compaction-image-offload`；重复注册会导致会话启动失败。

图片释放健康标记为 `imageOffloadMode: after-turn-v1`。DSH 原生会话禁止在事件发布回调中再次追加事件，插件在轮次结束回调返回后执行释放并持久化；恢复会话时，也处理已完成轮次留下的图片输入。

## 消耗控制

- 每个消息批次最多 4 张图片，最长边缩小至 1280 像素，每张传输上限 768 KiB。
- 图片准备共用 75 秒期限；生成沿用插件的轮次超时设置。
- 图片只在本次识图中进入模型。成功完成后追加原生 `image/offload` 事件，后续轮次使用占位引用，避免持续提交历史图片。
- 原始 DSH 附件记录仍保留；之后要再次看图，可重新发送图片。
- 同一消息批次的模型结果会缓存，发送失败时重试已有回复。

图片首次进入配置的模型服务时会产生图片输入消耗。云端模型会接收所选图片；本机解码不意味着模型推理也发生在本机。

## 无法读图时

`IMAGE_LOCAL_COPY_UNAVAILABLE` 表示对应图片没有可解码的本机文件。先在电脑微信打开该图片，等待下载。该流程使用已经在本机的文件，不会代替微信下载远端原图。

`IMAGE_MESSAGE_IDENTITY_NOT_FOUND` 表示无法用完整身份匹配原始图片消息；不要用其他聊天中的同号消息替代。

`NATIVE_IMAGE_SERVICES_UNAVAILABLE` 表示 DSH 没有提供原生附件或模型服务。核对 DSH 安装版本和插件加载状态。

排查日志位于 `state/logs/`。图片引用索引与解码缓存位于 `state/media/`，均属于私有运行数据，不应分享或提交。图片问题可通过桌面日志及数据库读取检查排查。

普通启动不回放历史消息。需要补测升级前收到的图片时，可由带读取器令牌的本机调用显式重试已登记图片；重试仍检查当前账号、当前白名单和原消息身份，每个运行周期同一图片只推送一次。

已登记表情包也支持上述图片重试接口。认证的 `POST /api/v1/events/retry` 可显式重试一条媒体或拍一拍，JSON 字段为 `conversationId`、`localId`、`createTime` 和字符串 `serverId`；必须完整匹配当前白名单里的原始入站消息，正文最多 1 KiB。接口不会批量重放历史，也不允许任意文字消息注入。
